# 爻语自举解释器

**用爻语自己写的爻语解释器。** 它实现了完整的 词法分析 → 语法分析 → 求值 → 执行 四层，
能够解析并执行爻语代码，**包括它自己的 1862 行源码**。

这正是自举（self-hosting）的判定标准：一门语言有能力实现自己的编译器/解释器。

---


> **运行方式**（两种都行，exe 不需要装 Python）
>
> ```powershell
> 爻语\解释器\exe\yao.exe 程序.yao      # 推荐：单文件，无依赖
> 爻语\解释器\exe\yao.exe 程序.yao        # 备选：开发时用，功能更全
> ```
>
> **能力差异**：`yao.exe`（C 版）支持语言核心语法、75 个内置函数里的 48 个，
> 但**不含** Web 服务、MQTT、Modbus TCP。做网页后端或工业物联请用 Python 版。
> 完整对照见 [手册.md](手册.md#解释器版本对照)。

## 架构

自举解释器完全按爻语的风格写，**没有任何面向对象，没有类和继承**，
用「表 + 函数」组织数据，用「环境链」实现作用域：

```
源码字符串
    ↓  切分()
记号列表（每个记号是表：{类, 文, 行, 列}）
    ↓  解析程序()
AST（每个节点是表：{型, ...}）
    ↓  执行语句们(程序, 环境)
结果
```

### 环境链

作用域用父子链表表示，没有类：

```yao-fragment
匠 新环境(父) 【
  归 { "变量" ⇒ {}, "父" ⇒ 父 }
】
```

查找时沿父链递归：

```yao-fragment
匠 环境查找(境, 名号) 【
  取(境["变量"], 名号, 缺) 名 值
  判 【
    值 != 缺 ⇒ 归 { "有" ⇒ 真, "值" ⇒ 值 }
    它 ⇒ 空
  】
  判 【
    境["父"] == 空 ⇒ 归 { "有" ⇒ 假, "值" ⇒ 空 }
    它 ⇒ 归 环境查找(境["父"], 名号)
  】
】
```

### 表达式解析：优先级爬升

避免 9 层递归（或→且→非→比较→加减→乘除→一元→后缀→基本），
改用单函数 + 优先级表：

```yao-fragment
匠 优先级表() 【
  归 {
    "或" ⇒ 1, "且" ⇒ 2,
    "==" ⇒ 3, "!=" ⇒ 3,
    "<" ⇒ 4, ">" ⇒ 4, "<=" ⇒ 4, ">=" ⇒ 4,
    "+" ⇒ 5, "-" ⇒ 5,
    "*" ⇒ 6, "/" ⇒ 6, "%" ⇒ 6
  }
】

匠 解析表达式(法, 最低优先级) 【
  解析一元(法) 名 左
  优先级表() 名 表
  循 真 【
    当前优先级(法, 表) 名 级
    判 【 级 <= 0 ⇒ 断 它 ⇒ 空 】
    判 【 级 < 最低优先级 ⇒ 断 它 ⇒ 空 】
    当前记号(法) 名 运记
    进记号(法)
    解析表达式(法, 级 + 1) 名 右
    { "型" ⇒ 运算符节点型(运记["文"]), "左" ⇒ 左, "右" ⇒ 右, ... } 名 合成
    合成 易 左
  】
  归 左
】
```

## 开发过程踩的坑（都是爻语语义的真实约束）

自举一个语言会把你对这门语言的所有含糊理解都逼出来。以下是实际遇到的：

### 1. `易` 不改变执行流程

```yao-fragment
循 继续 【
  判 【 级 <= 0 ⇒ 假 易 继续 它 ⇒ 空 】
  显("这行还是会执行")     ← 本轮剩余语句照跑
】
```

`假 易 继续` 只是把变量改成假，**当前这一轮的剩余语句仍然执行**，
下一轮开头才检查循环条件。要立即跳出必须用 `断`。

第一次写时我用了 `假 易 继续` 想提前退出，结果解析器陷入死循环。

### 2. `断` 只能在循环里用

```yao-fragment
判 【 是文(法, "】") ⇒ 断 它 ⇒ 空 】    ← 如果这行不在循环内，语法错误
循 要项 【 ... 】
```

正确写法是先算好条件再进循环：

```yao-fragment
假 名 要项
判 【 是文(法, "】") ⇒ 空 它 ⇒ 真 易 要项 】
循 要项 【 ... 】
```

### 3. 表字面量是「值」，不是「引用」——但赋值是引用

```yao-fragment
[] 名 空列
空列 名 参值们        ← 参值们 和 空列 是【同一个列表】
增(参值们, 1)         ← 空列 也变成 [1] 了！
```

这个坑让自举解释器的所有函数调用共享同一个参数列表，
导致第二次调用时环境混乱。

修法：用 `切([], 0, 0)` 每次创建新列表。

### 4. 换行不结束语句 —— `[]` 紧跟表达式会被当成索引

```yao-fragment
进记号(法)
[] 名 键们
```

会被解析成 `进记号(法)[]`（索引访问空下标），语法错误。

修法：避免以 `[]` 开头的新语句紧跟在表达式语句后面，
或改用 `切([], 0, 0) 名 键们`。

### 5. `判` 的分支臂是任意表达式，不只是 真/假/它

```yao-fragment
判 【
  码 == 32 ⇒ 归 真         ← 臂模式是任意表达式
  码 == 9  ⇒ 归 真
  它 ⇒ 归 假                ← 兜底臂
】
```

最初我只实现了 `真 ⇒ ...` / `它 ⇒ ...` 三种固定臂，遇到 `码 == 32` 就失败。

### 6. 型() 对表永远返回 "表"

```yao-fragment
型({ "型" ⇒ "匠", ... }) == "匠"     ← 永远为假！
取(被调, "型", "") == "匠"            ← 正确
```

判断自制「函数对象」的类型必须读它的字段，不能用 `型()`。

### 7. Python 栈深不够

自举解析 1862 行源码时递归很深，Python 默认递归限制（1000）和默认线程栈（约 8MB）
都不够，会 C 栈溢出（0xC00000FD）。测试里用 64MB 栈线程 + `setrecursionlimit(30000)`。

```python
threading.stack_size(64 * 1024 * 1024)
sys.setrecursionlimit(30000)
```

### 8. 表转字符串没有环检测 → 无限递归

自举解释器的环境链是**自引用结构**（环境的 `父` 指向另一个环境，
最终回到根）。`显(环境)` 时会无限递归调用 `转字`。

修法：在 `values.py` 的 `转字()` 里加环检测：

```python
def 转字(值, _路径=None):
    ...
    if isinstance(值, (list, dict)):
        路径 = _路径 or frozenset()
        标识 = id(值)
        if 标识 in 路径:
            return "[…]" if isinstance(值, list) else "{…}"
        路径 = 路径 | {标识}
        ...
```

## 覆盖的语法

| 类别 | 支持 |
|---|---|
| 字面量 | 数、字、真、假、空、列 `[..]`、表 `{..}` |
| 绑定 | `值 名 变量`、`新值 易 变量` |
| 运算 | `+ - * / %`、`== != < > <= >=`、`且 或 非`、一元 `-` |
| 访问 | `x[下标]`、`x.成员`、`f(...)` 调用、链式 `f(1)(2)` |
| 函数 | `匠 名(参) 【 】`、匿名 `节 (参) 【 】`、递归、闭包 |
| 控制 | `判 【 臂 】`（任意表达式臂）、`循`、`遍`、`断`、`续`、`归` |
| 异常 | `试 【 】 捕 误 【 】`、`抛` |
| 注释 | `注` |

## 意义

自举说明了三件事：

1. **爻语的表达能力足够**——不需要类和继承，用表和函数就能实现完整的解释器
2. **爻语的语法自洽**——它自己的语法规则能被自己的语法分析器完整解析
3. **实现是完整的**——不是玩具子集，而是覆盖了全部 29 个关键字和 73 个内置函数中的核心部分

同时它也是爻语最好的「综合测试用例」：1862 行、98 个函数、9655 个记号，
任何语法或语义的回归都会立刻让自举失败。
